# راه‌اندازی روی منابع واقعی (Eways + Hamrahtel)

پروفایل آماده: `config.real/` — منبع‌های `eways` (ریال) و `hamrahtel` (تومان) داخلش تعریف شده‌اند.

## ۱) نصب (یک‌بار)
```bash
pip install -r requirements.txt -r requirements-sources.txt
playwright install chromium
```

## ۲) اطلاعات ورود Eways
فایل `.env` کنار پروژه بسازید (از `.env.example` کپی کنید؛ در git نمی‌رود):
```
EWAYS_USERNAME=شماره‌موبایل-یا-یوزرنیم
EWAYS_PASSWORD=پسورد
```
Hamrahtel ورود نمی‌خواهد.

## ۳) محصولات دلخواه
`config.real/watchlist.yaml` را ویرایش کنید (برند، مدل دقیق مثل `iPhone 17 Pro`، ظرفیت، رم، ریجن اگر مهم است).

## ۴) بررسی سلامت منابع
```bash
python -m pricecompare --config-dir config.real check-sources
```
انتظار: هر دو `ok` و تعداد محصولات ≥ ۲۰. Hamrahtel با مرورگر کار می‌کند و چند دقیقه طول می‌کشد.

## ۵) اجرای آزمایشی (چیزی نوشته نمی‌شود)
```bash
python -m pricecompare --config-dir config.real run --dry-run
```
سپس اجرای واقعی و بازبینی:
```bash
python -m pricecompare --config-dir config.real run
python -m pricecompare --config-dir config.real match-report --status REVIEW   # تطبیق‌های نامطمئن
python -m pricecompare --config-dir config.real explain iphone17-256           # چرا این قیمت انتخاب شد
```
خروجی‌ها در `data/real/out/` هستند (`report.md` برای خواندن، `output.json` برای برنامه).

## ۶) کنترل‌های حتماً لازم قبل از اعتماد به عدد‌ها
1. **واحد Eways:** قیمت ۲–۳ محصول را با پنل Eways مقایسه کنید. در `output.json` باید `price_raw` (ریال) ده برابر `price_toman` باشد. اگر برعکس بود، `currency_unit: toman` بگذارید.
2. اگر هشدار «احتمال خطای واحد ریال/تومان» آمد، همین مورد است.
3. قیمت یک محصول را با سایت Hamrahtel مقایسه کنید.
4. در `match-report --status NO_MATCH` ببینید چیز درستی رد نشده باشد؛ اصلاح دستی در `config.real/overrides.yaml`.

## ۷) تلگرام — سه چیز باید همزمان درست باشد
اگر پیامی نیامد، معمولاً یکی از این سه مورد است (برنامه حالا در لاگ صریح می‌گوید کدام: خط `telegram: ...`):
1. **تنظیمات:** در `config.real/settings.yaml` باید `telegram_enabled: true` و `telegram_dry_run: false` باشد.
2. **اطلاعات ربات:** `TELEGRAM_BOT_TOKEN` (از @BotFather) و `TELEGRAM_CHAT_ID`.
   - به ربات خودتان (یا گروه) یک پیام بدهید، سپس در مرورگر باز کنید: `https://api.telegram.org/bot<TOKEN>/getUpdates` و مقدار `chat.id` را بردارید (برای گروه معمولاً با `-` شروع می‌شود).
   - روی GitHub: Settings → Secrets and variables → Actions → دو secret با همین نام‌ها بسازید. روی سیستم خودتان در `.env` بگذارید.
3. **اجرای واقعی:** `--dry-run` هیچ‌چیز نمی‌نویسد و نمی‌فرستد. workflow حالا بدون `--dry-run` اجرا می‌شود.

رفتار پیش‌فرض: پیام فقط وقتی فرستاده می‌شود که نسبت به **آخرین پیام ارسال‌شده** قیمتِ برنده‌ی یک واریانت حداقل `telegram_min_change_pct` (پیش‌فرض ۰٫۵٪) تغییر کرده باشد، یا واریانتی اضافه/حذف شده باشد. جابه‌جاییِ فقط «منبع برنده» با قیمت تقریباً برابر پیام نمی‌سازد. وضعیت در `data/real/telegram_state.json` است و با `actions/cache` بین اجراها می‌ماند.
اجرای دستی روی GitHub: Run workflow → گزینه‌ی `send_telegram` را برای آزمایش خاموش کنید.

## ۸) نحوه‌ی خواندن Hamrahtel
سایت Hamrahtel یک API از نوع GraphQL دارد که قیمت (عدد دقیق)، رنگ و موجودی واقعی (`quantityAvailable`) را می‌دهد. با `strategy: auto`
اول همان خوانده می‌شود و متن صفحه فقط پشتیبان است. در لاگ کنار وضعیت منبع می‌بینید:
`[strategy=graphql (graphql=N, text=M)]`. اگر N و M نزدیک هم باشند خوانش سالم است؛ اگر `strategy=text` دیدید یعنی API گرفته نشد.
آدرس صفحه‌ی هر محصول هنوز ناشناخته است، پس لینک همان صفحه‌ی دسته است (`product_url_template` برای بعد).

## ۹) عیب‌یابی تطبیق
اجرا با `--show-offers 12` برای هر منبع نمونه‌ی واقعی عنوان‌ها، ویژگی‌های استخراج‌شده و دلیل تطبیق/ردشدن را چاپ می‌کند (workflow هم همین را می‌زند). اگر محصولی «پیدا نشد» ولی در سایت هست، آن بخش لاگ را بفرستید.

## نکات
- Eways پنل عمده‌فروشی با ورود است؛ از حساب خودتان و مطابق شرایط استفاده‌ی آن استفاده کنید. فاصله‌ی اجراها را کم نکنید (پیش‌فرض workflow: هر ۳ ساعت).
- جزئیات محصول (رنگ/رم/ظرفیت دقیق) فقط برای محصولات هم‌خوان با watchlist خوانده می‌شود (`details: candidates`)، نه کل کاتالوگ.
- اگر Hamrahtel صفر محصول برگرداند، منبع «شکست‌خورده» حساب می‌شود و خروجی قبلی حفظ می‌شود.

## رنگ‌های هم‌معنی در دو فروشگاه
اگر یک رنگ در دو فروشگاه اسم متفاوت دارد (مثلاً «آبی» و «آبی روشن») و مطمئنید یکی هستند، در `config.real/overrides.yaml` بخش `color_merge` را پر کنید تا قیمت‌ها با هم رقابت کنند (نمونه داخل فایل هست).

## حالت «همه‌ی گوشی‌ها» (Discovery) و پست‌های تلگرام
- در `config.real/watchlist.yaml` بخش `discovery.enabled: true` باعث می‌شود **همه‌ی گوشی‌های هر دو فروشگاه** مقایسه شوند، نه فقط چند محصول انتخابی. یک مدل در دو فروشگاه خودکار یکی می‌شود (خط مدل، Pro/Max/Ultra، 4G/5G، ظرفیت، رم، ریجن و اکتیو باید یکی باشند؛ ریجن/اکتیوِ نامشخص «جوکر» است ولی دو ریجن مختلف هیچ‌وقت قاطی نمی‌شوند).
- برای هر **رنگ** جداگانه ارزان‌ترین قیمتِ معتبر (موجود، تازه، غیرپرت) انتخاب می‌شود. «آبی» و «آبی روشن» یک رنگ حساب می‌شوند.
- `min_sources: 2` فقط گوشی‌هایی را نشان می‌دهد که حداقل دو فروشگاه دارند (مقایسه‌ی واقعی). `brands` و `exclude_regex` برای فیلتر.
- پست‌های تلگرام: یک پست سرصفحه (وضعیت منابع) + یک پست برای هر برند. `telegram_group_by: product` یعنی یک پست برای هر گوشی، `none` یعنی یک پست بلند. حداکثر `telegram_max_messages` پست.
- `telegram_mode: changes_only` فقط رنگ‌هایی را می‌فرستد که قیمتشان تغییر کرده (همراه قیمت قبلی ▼▲)؛ اولین بار همه را می‌فرستد.
- لینک‌هایی که برای ۳ خط یا بیشتر یکسان باشند (مثلاً صفحه‌ی دسته‌ی Hamrahtel) چاپ نمی‌شوند.
